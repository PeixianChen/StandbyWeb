# Stand:by 网站维护说明

这是一个以手机为主、同时适配平板和电脑的单页网站，共 7 个版面。页面中的**所有标题、文字和图片**都来自 `content/` 文件夹，HTML 里没有写死任何内容。

日常更新只需要：改 `content/` 里的文件 → 运行一次索引命令 → 提交推送。不需要改 HTML、CSS 或 JavaScript。

## 屏幕适配

页面以 760px 宽度为界，分两套排版：

- 窄于 760px（手机、平板竖屏）：手机排版，所有尺寸按屏幕宽度等比计算，320px 的小屏和 430px 的大屏比例完全一致；更宽的屏幕上字号不再继续放大。
- 760px 及以上（平板横屏、电脑）：宽屏排版，内容最宽 1200px 居中，字号适中。专场一次显示 7 张海报，合作资源拼贴改为 10 列，专场详情改为居中弹窗。

拖动浏览器窗口改变宽度时，排版会实时切换。

## 目录结构

```text
standby_web/
├── content/                  全部页面内容（日常只改这里）
│   ├── 01_hero/              首屏
│   ├── 02_figures/           核心数据
│   ├── 03_ip/                综艺 IP
│   ├── 04_scenes/            现场照片
│   ├── 05_shows/             专场演出
│   ├── 06_artists/           签约演员
│   ├── 07_resources/         合作资源
│   └── index.json            自动生成的索引，不要手动编辑
├── fonts/                    英文与数字字体 Jost（附授权文件）
├── scripts/                  内容检查与索引生成脚本
├── index.html                页面外框
├── script.js                 读取 index.json 并渲染 7 个版面及其交互
└── styles.css                样式（手机排版与宽屏排版）
```

## 通用规则

### 版面文件夹

格式为 `两位数字_类型`，例如 `02_figures`。

- 数字决定版面在页面上的先后顺序，可以修改数字来调整顺序。
- 下划线后面的类型**不能改**，它决定这个版面用哪种排版和交互。可用类型：`hero`、`figures`、`ip`、`scenes`、`shows`、`artists`、`resources`，每种只能出现一次。
- 删除某个版面文件夹，页面上就不再显示这个版面。

### 版面通用文字

除首屏外，每个版面文件夹里都可以放：

| 文件 | 是否必填 | 作用 |
| --- | --- | --- |
| `title.txt` | 必填 | 版面中文标题，例如「核心数据」 |
| `subtitle.txt` | 可选 | 标题上方的英文小字，例如「Key Figures」 |
| `note.txt` | 可选 | 版面底部的灰色说明文字 |
| `background.*` | 可选 | 整个版面的底图，会自动压暗并与上下版面渐变衔接。横图、竖图都可以，主体尽量居中 |
| `background-credit.txt` | 可选 | 底图作者与授权记录，不会显示在网页上 |

### 条目文件夹

版面里的每一项内容（一个数据、一场专场、一位演员……）是一个子文件夹，格式为 `三位数字_名称`，例如 `000_小鹿`。

- 数字决定显示顺序，从小到大排列；可以不连续，但同一版面内不能重复。
- 下划线后的名称只用来方便识别，网页显示的文字以 txt 文件为准。

### 文件格式

- 文字文件必须是 UTF-8 编码的 `.txt`，必填的文件不能为空。
- 图片支持 `webp`、`jpg`、`jpeg`、`png`、`svg`，优先使用 WebP。文件名用小写，例如 `poster.webp`，同一种图片只能保留一个格式。
- 单张图片不得超过 **1 MB**，超过会导致检查失败。

## 各版面说明

### `01_hero` 首屏

| 文件 | 是否必填 | 作用 |
| --- | --- | --- |
| `logo.*` | 必填 | 中间的大 Logo。黑底白字的图片会自动去掉黑底 |
| `title.txt` | 必填 | Logo 下方的主标语 |
| `subtitle.txt` | 可选 | 主标语下方的英文小字 |
| `cta.txt` | 可选 | 底部引导文字，默认为「向下浏览」 |
| `background.*` | 可选 | 背景图，会自动压暗并缓慢移动。推荐竖图或 3:2 横图，主体居中 |
| `background-credit.txt` | 可选 | 背景图作者与授权记录，不会显示在网页上 |

### `02_figures` 核心数据

每个数据一个条目文件夹：

- `label.txt`：数据名称，例如「全年巡演」。
- `value.txt`：数值，例如「400场」。末尾的中文单位会自动变成小号红字，前面的数字越长字号越小，保证一行放得下。

数据窗口会自动上下轮播，也可以手动滑动或点击箭头。

### `03_ip` 综艺 IP

每个 IP 一个条目文件夹：

- `title.txt`：IP 名称，例如「《喜人奇妙夜》全国巡演」。
- `image.*`：海报，会铺满整个屏幕，超出屏幕比例的部分从中间向外裁掉。手机上建议用竖版海报（9:16 左右，宽度至少 1080px），横图在手机上只能显示中间一部分。

每张海报占满一屏，标题压在海报底部。

### `04_scenes` 现场照片

照片直接放在版面文件夹里（不需要子文件夹），文件名格式为 `三位数字_照片说明.webp`，例如 `000_上海专场.webp`。下划线后的文字用作图片说明。

照片分两行反向自动滚动，可以手动左右滑动，触摸时暂停。高度固定、宽度按原图比例，推荐横图，宽度 800px 左右。

### `05_shows` 专场演出

每个专场一个条目文件夹：

| 文件 | 是否必填 | 作用 |
| --- | --- | --- |
| `artist.txt` | 必填 | 演员名 |
| `title.txt` | 必填 | 专场名称，不需要加书名号，页面会自动加 |
| `description.txt` | 可选 | 详情弹层里的介绍，可以换行 |
| `poster.*` | 必填 | 海报。推荐 3:4 竖图，720 × 960 px |
| `detail.*` | 可选 | 详情弹层使用的高清图；没有时使用海报 |

海报排成一横排，中间最大、两侧依次变小，每隔几秒自动切换到下一张，也可以左右滑动、点箭头或点两侧海报切换。点击中间的海报会从底部弹出详情。

### `06_artists` 签约演员

每位演员一个条目文件夹：

| 文件 | 是否必填 | 作用 |
| --- | --- | --- |
| `name.txt` | 必填 | 演员名 |
| `role.txt` | 可选 | 身份介绍 |
| `photo.*` | 必填 | 肖像，显示为 4:5 竖图，推荐宽度 800px |
| `focus.txt` | 可选 | 取景位置，格式见下 |

`focus.txt` 只写一行，三个值用空格分开：`横向位置 纵向位置 放大倍数`，例如 `72% 26% 1.75`。

- 横向位置：0% 为最左、100% 为最右。
- 纵向位置：0% 为最上、100% 为最下。
- 放大倍数：1 为不放大。原图是带大量文字的海报时，可以放大到 1.5～2 只保留人物。

肖像排成一横排，默认第一位最大，点击（电脑上鼠标移到）其他演员时，该演员放大并显示身份介绍，其他人稍小。演员较多时这一排可以左右滑动。

### `07_resources` 合作资源

每个资源一个条目文件夹，根据放入的图片自动决定样式：

| 放入的文件 | 显示方式 |
| --- | --- |
| `image.*` | 照片块，图片铺满，底部显示 `title.txt` |
| `logo.*` | Logo 块，浅色底，Logo 完整显示 |
| 都没有 | 文字块，显示 `title.txt` 和 `note.txt`（适合「素材待补」的占位） |

- `title.txt` 必填，`note.txt` 可选。
- 拼贴会自动排版，不留空洞，每隔几秒放大一块，其余块错位让开；点击任意一块即可放大它。

## 生成索引与本地预览

修改 `content/` 后，在项目根目录运行：

```bash
node scripts/generate-indexes.mjs
```

脚本会检查命名、编号、必填文件和图片体积，并生成 `content/index.json`。有问题时会停止并指出具体文件，修复后重新运行即可。

本地预览：

```bash
python3 -m http.server 8000
```

然后在浏览器打开 `http://localhost:8000/`。建议在浏览器开发者工具中切换到手机模式预览。不要直接双击 `index.html` 打开，浏览器会阻止网页读取 `index.json`。

## 自动部署

`.github/workflows/deploy-pages.yml` 会在代码推送到 `main` 分支后自动运行索引检查并发布到 GitHub Pages。内容不符合规则时部署会失败，线上的旧版本不会被错误内容覆盖。

## 提交前检查清单

- 版面文件夹是否为 `两位数字_类型`，条目文件夹和照片是否为 `三位数字_名称`。
- 同一版面内是否有重复编号。
- 必填的 txt 是否齐全、非空，并使用 UTF-8 编码。
- 图片是否压缩过，单张是否在 1 MB 以内。
- 是否运行过 `node scripts/generate-indexes.mjs`，并一起提交了 `content/index.json`。
- 是否在手机尺寸下预览过。
